# MCP 与桌面应用联动

当前源码中，MCP 作为运行中 KankanBan 的客户端。桌面主窗口统一执行工具请求、保存数据，再向卡片窗口广播快照。MCP 不打开独立写会话、不取得工作区锁、不直接写存档。

> 已发布的 v0.0.0.1 安装包尚未包含此桥接实现。验证新功能请从最新源码运行桌面应用；本文命令行示例使用本次验证环境 Node.js 24。

## 安装版 MCP（本轮新增，尚未发布）

新安装包附带独立的 `kankanban-mcp.exe`，无需 Node.js 或项目源码。打开管理器的设置 → MCP 接入，复制配置到支持 stdio MCP 的客户端。配置中的 command 是安装目录内该程序的完整路径，args 默认为空。使用时保持桌面应用打开；程序每次请求跟随桌面当前工作区，应用关闭时会返回连接错误。

该程序只承担协议和本机桥接，不直接修改卡片文件。工具目录由源码定义生成；署名、操作记录阅读检查和业务校验仍由共享逻辑处理。截图仍返回 MCP image 内容块。标准协议遵循 [MCP stdio 传输](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)。

开发构建：`npm run build:mcp` 生成独立 Rust 程序与 Tauri externalBin 资源；`npm run app:build` 会自动先构建它再打包。开发者需要 Rust 和 Node.js，安装包用户不需要。协议测试：构建后运行 `node --import ./test/tsx-hooks.mjs --test test/mcp-release*.test.ts`；Rust 测试：`cargo test --manifest-path src-mcp/Cargo.toml`。

工具清单 `src-mcp/tools.json` 在构建时生成，勿手工修改。新增或修改工具后重新构建 MCP 程序。可选第一个命令行参数固定工作区；默认不传，自动跟随应用选择。配置中不包含桥接令牌。

## 启动

先在 `KankanBan/` 中启动桌面应用：

```powershell
npm run app
```

MCP 客户端通过 stdio 启动源码入口。无需手动填写端口或凭据：

```json
{
  "mcpServers": {
    "KankanBan": {
      "command": "node",
      "args": ["C:/你的项目目录/Kaban/KankanBan/src/mcp/main.ts"]
    }
  }
}
```

不传工作区路径时，每次调用都会读取应用当前选择的工作区，切换工作区后无需重新配置。需要固定工作区时，在 `args` 末尾追加该目录的绝对路径；它未在桌面打开时返回错误，不会转为直接写文件。

可在项目目录用 `npm run mcp` 启动相同适配器，但 stdout 是协议通道，不应把它当作交互命令行使用。

## 工具与一致性

共 31 个工具。保留原有 13 个：卡片创建、字段编辑、布局切换、移动、删除、撤销；读取树、卡片、子卡和搜索；预制体实例化、解除关联与呈现引用。新增：

| 范围 | 工具 |
| --- | --- |
| 协作 | `identify_actor`、`read_operations`、`ack_operations` |
| 涂鸦 | `get_doodle`、`add_doodle_strokes`、`remove_doodle_strokes`、`clear_doodle` |
| 位置与同步 | `get_card_location`、`reorder_card`、`move_card_in_canvas`、`sync_prefab` |
| 工作区 | `get_workspace`、`switch_workspace` |
| 窗口 | `list_windows`、`open_card_window`、`close_card_window`、`inspect_window`、`capture_window` |

涂鸦坐标使用正文文档或灵感台平面坐标；笔迹与界面铅笔共用文字色和 3px 线宽，无专属颜色或线宽参数。`set_field` 禁止修改 `/doodle` 及其子路径，应使用专用工具。文档的 width/height 是绘图区尺寸。

`reorder_card` 的 index 是同一父卡下的最终索引。`move_card_in_canvas` 使用灵感台平面坐标，遵循界面移动和预制体规则。

`inspect_window` 返回窗口 CSS 坐标、正文绘图区、滚动位置和可见子卡几何信息；灵感台还返回缩放、平移和平铺尺寸。`capture_window` 仅捕获本应用管理器或卡片窗口的 WebView 内容，以 MCP image 内容块返回 PNG，不能截取其他应用或整个桌面。

`switch_workspace` 接受现有目录的绝对路径，null 表示回默认工作区。先验证路径并保存草稿，返回 scheduled 后执行重载；重载后用 `get_workspace` 确认。固定路径客户端仍固定原路径，跟随应用的客户端无需改配置。

写请求先收集窗口草稿，进入与 GUI 相同的串行队列。保存成功后返回结果并同步窗口；读取也经过队列，避免读到旧文件快照。创建、布局、移动和删除使用共享业务动作；MCP 创建的卡片以声明的 AI 身份 ID 记录 createdBy，卡片事件携带 actor 署名。只读请求查询已保存状态，不强行结束用户编辑；写请求保存草稿后再次校验阅读凭据。

看板仍固定三列，不能通过 MCP 创建第四个直接子节点。删除仍是级联删除，预制体和实例的规则与桌面操作相同。

## 署名与先读后操作

自动保存、协作日志与 AI 阅读分开处理：核心恢复／撤销日志继续逐次保存数据，个人窗口与浏览状态保存到本机视图文件；协作日志不再新增这类个人状态。正文／标题连续输入在 2 秒以内的保存间隔内合并，删除、树位置移动、涂鸦等独立动作单独保留。合并期间最新协作编辑与恢复游标原子保存在 `.kkb/operations-state.json`，覆盖写入而不逐次追加；读取、显式刷新或另一项内容操作会将其固定到 `operations.jsonl`。已读取记录不会再被改写，随后新增的内容变化仍会阻挡旧阅读凭据。

旧协作日志文件保留，但其中个人浏览状态在建立 AI 阅读索引时跳过。`details=true` 展开协作记录细节，已合并的编辑不会恢复成逐字输入流水。原始细粒度恢复／撤销事件仍属于保存层，不作为 AI 默认阅读内容。

用户在设置中的“操作署名”填写名字或昵称；未填写时明确标记“用户（未设置署名）”。AI 每次建立连接后先调用：

```json
{"name":"identify_actor","arguments":{"id":"codex","name":"Codex"}}
```

同一 AI 保持 id 稳定，不同 AI 使用不同 id。署名是参与者自行声明的身份，不是账号认证。桌面应用生成时间戳，不能由工具调用者填写或回填。

再调用 `read_operations`。首次返回全部他人操作，每页最多覆盖 100 条原始记录；如果有 nextCursor，继续传 cursor 读取下一页，直到取得 reviewToken。读完后调用 `ack_operations` 确认收到。下一个普通工具调用或后续读取也会确认已经返回完整记录的凭据。

确认后的阅读进度按 AI 身份保存在当前工作区的 `.kkb/mcp-readers.json`，重连或应用重启后先读取新增部分。新连接仍必须先调用 read_operations，不能凭已有进度直接修改。未确认的响应不会推进持久进度；未读完分页也不会取得新凭据。切换工作区使用对应目录下的进度；缓存损坏或历史替换会安全地从头读取。需要主动回顾历史时传 all=true。

默认返回简短变更摘要。同一参与者连续修改同一卡片的标题或正文，可合并为一项，保留 seqStart/seqEnd、count、起止时间和净变更。删除、移动、撤销和不同字段之间不会合并。sourceCount 是本页覆盖的原始条数。原始日志不改动；传 details=true 可展开本次读取的记录，all=true 与 details=true 合用可回顾全部原始记录。

常驻客户端适用于需要从脚本持续调用的场景：

```powershell
npm run mcp:agent -- --id codex --name Codex
```

每行输入一个 JSON 调用，同一进程复用一个 SDK/stdio 连接：

```json
{"name":"read_operations","arguments":{}}
{"name":"ack_operations","arguments":{}}
{"name":"get_workspace","arguments":{}}
```

有 nextCursor 时先逐页读完，再确认；不能把上面的三行盲目作为固定批处理。返回 ready 表示身份声明成功，普通结果用 ok/result，错误用 ok/error；失败写入绝不自动重试。disconnect 退出。该入口使用普通 Node 进程，不依赖受限的 node_repl。

每个普通工具在桌面串行队列中校验凭据。未声明身份、未读完分页、或最后读取后其他参与者又产生操作，均拒绝执行并提示先读记录。读取后应重新决定下一步，不能自动重试原计划；尤其不能把用户删除的涂鸦画回来，或把用户已完成的任务移回进行中。协议可以保证记录返回和调用顺序，理解记录仍是 AI 的责任。

`.kkb/operations.jsonl` 是独立、持久的协作操作记录，包含序号、操作 ID、服务器时间戳（Unix 毫秒）、actor（kind/id/name）、操作类型和变更摘要。卡片、涂鸦、树结构、布局、预制体同步、设置、桌面展开/关闭及完成的窗口移动、缩放、模式切换都会记录。撤销作为新操作追加，不删除已有协作记录。浏览查询、悬浮、未保存输入和临时滚动位置不是变更记录。

旧卡片事件导入时保留原来的 clientId 与时间，标记为 legacy，不推测是哪个具体 AI 或用户；过去已经被旧撤销机制截断的事件无法补造。较长正文和大量变更提供摘要，完整当前内容用 read_card/get_doodle 查询。此文件是应用数据，不是开发者的个人工作日志。

## 连接边界

- 本机 TCP 仅绑定 `127.0.0.1`，使用系统生成的随机凭据；不是对外开放的 HTTP 服务。
- `.kkb/mcp-bridge.json` 是当前端口、工作区和临时凭据的发现文件，不应共享、上传或手动修改。前端数据加载与应用备份会排除它。
- 凭据在界面重新连接时更新；适配器每次请求重新读取发现文件。
- 仅主窗口可领取、确认和回复请求；工具名和参数在桌面边界再次校验。
- 请求限 1 MiB，响应在客户端限 16 MiB，最多 8 个同时连接。等待桌面回复超过 30 秒即超时，未开始执行的过期请求不会再写入。
- 已开始执行的写操作若超时，可能已经提交。适配器不自动重试，先读取状态确认后再决定下一步。
- 关闭应用或切换工作区会关闭旧桥接，旧连接不能写入新工作区。CLI 仍是独立写者，与桌面互斥；这次调整只改变 MCP 入口。

## 验收

已用命令行覆盖串行写入、持久化后的读取、通知订阅、MCP 协议与 TCP 适配、凭据更新、错误参数、看板规则及过期排队请求。Rust 检查覆盖随机凭据、鉴权和多余请求字段。调优检查覆盖确认后重连续读、分页未完成不确认、快照后新增记录不跳过、摘要及原始记录并存、增量索引避免全历史遍历、常驻连接保留身份与凭据且不重试失败写入。

真实 Tauri 窗口链路需要人工确认：保持应用打开，通过 MCP 创建或改名一张子卡，检查它即时出现在窗口；编辑窗口正文后让 MCP 读取；切换工作区再次调用；关闭应用后确认返回连接错误。没有自动启动 GUI 进行这些验证。
