# 程序文本

修改文字只需编辑 `zh-CN.json` 中对应条目的值。当前语言固定为中文，未提供语言切换。

## 后续开发必须遵守

**所有新增和修改的程序文案必须从多语言配置表读取，禁止直接写在业务代码或样式中。** 当前只有中文不影响此要求。

1. 先在 `zh-CN.json` 的对应模块添加或复用条目，再调用 `uiText`／`i18n::text`。
2. 动态数字、卡名、路径等作为参数传入。完整句子应作为一个条目，避免在代码里拼接语言片段。
3. 悬浮说明、无障碍标签、空状态、错误信息和命令行帮助同样需要接入；HTML/CSS 文案也应由文本入口注入。
4. 修改现有文案时修改配置表中的值；重命名条目或参数时同步更新调用方。
5. 交付前核对文本键存在、参数对应，并检查新增代码是否遗留面向用户的硬编码文字。

此要求仅适用于本项目，来源为用户 2026-10-09 的明确指示；项目根目录 `AGENTS.md` 也记录了此规则。

## 按模块查找

| 分组 | 内容 |
| --- | --- |
| `app` | 窗口标题、默认新卡名、空内容提示 |
| `webview/WorkspaceApp` | 管理器、设置、菜单、对话框 |
| `webview/PrototypeNote` | 独立卡片窗口与编辑提示 |
| `webview/PrefabSyncButtons` | 同步按钮与悬浮说明 |
| `webview/BreadcrumbTrail` | 面包屑说明 |
| `core/*` | 业务、保存、布局与同步错误 |
| `cli/*` | 命令行帮助与输出 |
| `mcp/*` | 工具说明与错误 |
| `native/*` | Rust 窗口、文件与系统操作提示 |

`text001` 等是稳定条目名，修改右侧文字即可。可以直接搜索当前界面上的措辞定位条目。

## 动态内容

例如 `app.newCardTitle` 的值是 `Card{arg0}`，其中 `{arg0}` 是节点 ID。
可以改为 `卡片 {arg0}`，也可以移动占位符的位置。保留所需参数名，不修改代码中的 ID、字段名或协议值。

TypeScript 调用：

```ts
import {uiText} from '../i18n/text.ts';
uiText('app.newCardTitle', {arg0: cardId});
```

Rust 调用：

```rust
crate::i18n::text("app.newCardTitle", &[("arg0", card_id.to_owned())])
```

新增文字时先在对应分组添加条目，再通过上述入口读取。TypeScript 的文本键有类型约束；两侧读取同一份 JSON。参数只替换一次，参数值里的花括号或美元符号不再被解释。

## 生效范围

前端开发环境会跟随文件更新；Rust 将文本表编译进程序，修改原生层文字后需要重新启动 `npm run app`。发行版本需要重新构建。

默认卡名及内置卡标题只用于新建数据；用户已保存的卡片标题和正文仍是卡片数据。图标符号、机器协议名称、存储字段、文件路径与应用打包元数据不作为翻译文案。
